به عنوان نویسنده‌ی Java 21 NFR Handbook و با توجه به کد نمره‌ی ۱۰ که برای Localization نوشتید، این‌ها را نکات طلایی Localization می‌نامم. این نکات دقیقاً تفاوت بین یک توسعه‌دهنده‌ای که "کد می‌نویسد" و یک Technical Lead سطح ۱۰ که "جهانی فکر می‌کند" را نشان می‌دهد:

------------------------------------------------------------------------------------------------------------------------

۱. اصل "جداسازی کامل متن از کد" (Separation of Concerns)
قانون طلایی: هیچ‌گاه متن‌های نمایشی را در کد Hard-Code نکنید.
شما با ResourceBundle این کار را کردید. اما نکته‌ی مهم این است که حتی خطوط خالی، فاصله‌ها و نشانه‌های نگارشی نیز باید در فایل‌های Properties قرار گیرند، نه در کد.
نکته‌ی Lead: "کد شما باید بدون هیچ متنی (به جز لاگ‌های سیستمی) قابل اجرا باشد. همه‌چیز باید از فایل‌های Properties بیاید."

------------------------------------------------------------------------------------------------------------------------

۲. اصل "فرمت‌کننده‌های استاندارد جاوا" (Standard Formatters)
شما از DateFormat و NumberFormat.getCurrencyInstance استفاده کردید که کاملاً درست است. اما نکته‌ی طلایی این است که هرگز از SimpleDateFormat با الگوی ثابت (مثلاً "yyyy/MM/dd") استفاده نکنید، زیرا این کار انعطاف‌پذیری را از بین می‌برد. همیشه از متدهای getDateInstance، getTimeInstance، و getDateTimeInstance با سبک‌های SHORT, MEDIUM, LONG, FULL استفاده کنید.
نکته‌ی Lead: "اگر الگوی تاریخ را خودتان تعیین کنید، برای کشورهای دیگر (مثل آمریکا که ماه/روز/سال است) اشتباه خواهد بود. بگذارید خودِ Locale تصمیم بگیرد."

------------------------------------------------------------------------------------------------------------------------

۳. اصل "ارز و اعداد با CurrencyInstance نه NumberInstance"
شما از NumberFormat.getCurrencyInstance استفاده کردید که عالی است. نکته‌ی مهم این است که getNumberInstance فقط عدد را فرمت می‌کند (با جداکننده‌های هزارگان) ولی نماد ارز را نمایش نمی‌دهد. اگر از CurrencyInstance استفاده کنید، جاوا به‌صورت خودکار:
نماد ارز ($, €, ¥, £) را بر اساس Locale انتخاب می‌کند.
جایگاه نماد را (قبل یا بعد از عدد) به‌درستی تنظیم می‌کند (مثلاً در فرانسه 1 250,50 € و در آمریکا $1,250.50).
جداکننده‌های هزارگان و اعشار را به‌درستی اعمال می‌کند.

------------------------------------------------------------------------------------------------------------------------

۴. اصل "استفاده از MessageFormat برای پارامترهای پویا"
اگر متن‌های شما شامل پارامترهایی مانند {0}, {1} هستند، از MessageFormat استفاده کنید. این کار:
جایگزینی پارامترها را به‌صورت استاندارد انجام می‌دهد.
از ChoiceFormat برای انتخاب جمع/مفرد (مثلاً 1 item در مقابل 2 items) پشتیبانی می‌کند.
به مترجم اجازه می‌دهد که جایگاه پارامترها را در جمله تغییر دهد (در زبان‌های مختلف ترتیب کلمات متفاوت است).

مثال:

properties
invoice.message=Dear {0}, your order of {1,number,currency} has been confirmed.
java
String msg = MessageFormat.format(bundle.getString("invoice.message"), customerName, amount);
۵. اصل "مدیریت Locale در لایه‌ی درخواست (Request Scope)"
در برنامه‌های وب، Locale باید از درخواست کاربر (مثلاً هدر Accept-Language مرورگر) گرفته شود، نه اینکه در کد Hard-Code شود. در کد شما، Locale را به‌عنوان پارامتر به سازنده می‌دهید که درست است، اما در برنامه‌های واقعی، این Locale باید پویا باشد.

۶. اصل "Fallback یا سقوط به عقب" (با سلسله‌مراتب ResourceBundle)
ResourceBundle به‌صورت خودکار یک سلسله‌مراتب را دنبال می‌کند:
زبان + کشور (مثلاً Messages_fr_CA)
فقط زبان (مثلاً Messages_fr)
زبان پیش‌فرض سیستم (مثلاً Messages_en)
در نهایت، اگر هیچ‌کدام موجود نبود، MissingResourceException پرتاب می‌شود.
نکته‌ی Lead: "همیشه یک فایل پیش‌فرض (مثلاً Messages_en.properties) داشته باشید تا در صورت نبود فایل زبان کاربر، برنامه از کار نیفتد."
۷. اصل "تست Localization در زمان اجرا"
برای تست Localization، از Locale.setDefault() برای تغییر موقت Locale سیستم استفاده کنید و تست‌های واحد بنویسید:

java
Locale.setDefault(Locale.FRANCE);
// کد شما
اما توجه کنید که این کار برای تست‌های واحد ایمن است، نه برای محیط تولید.

------------------------------------------------------------------------------------------------------------------------

۸. اصل "مدیریت فایل‌های Properties با Encoding صحیح"
فایل‌های Properties به‌صورت پیش‌فرض با ISO-8859-1 (Latin-1) ذخیره می‌شوند که از کاراکترهای غیرانگلیسی (مانند é, ä, ç) پشتیبانی نمی‌کند. برای پشتیبانی از UTF-8، باید در هنگام بارگذاری، Charset را مشخص کنید (در جاوا ۹ به بعد):

java
ResourceBundle bundle = ResourceBundle.getBundle("Messages", locale, Control.INSTANCE);
یا از ابزار native2ascii برای تبدیل استفاده کنید.

خلاصه‌ی طلایی برای پاسخ‌دهی در آزمون (۴ کلمه):
اگر سوالی با NFR = Localization آمد، این ۴ کلمه را در ذهن داشته باشید:

Bundle (استفاده از ResourceBundle)
Format (استفاده از DateFormat و NumberFormat)
Locale (تعیین Locale پویا)
Separate (جداسازی کامل متن از کد)
