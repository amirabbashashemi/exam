🥇 بخش اول: چک‌لیست ۵ ثانیه‌ای Archiveability (قبل از تحویل کد)
وقتی کد را نوشتید، این ۵ سوال را از خودتان بپرسید:

آیا داده‌ها اول در بایگانی ذخیره می‌شوند و بعد از حافظه حذف می‌شوند؟
(اگر برعکس باشد → داده‌ها را از دست می‌دهید! Atomicity رعایت نشده است)

آیا لایه‌ی بایگانی از لایه‌ی اصلی کاملاً جدا شده است؟
(اگر OrderService خودش مسئول نوشتن در فایل باشد → نقض Single Responsibility)

آیا می‌توانم استراتژی بایگانی را بدون تغییر در OrderService عوض کنم؟
(اگر برای تغییر از FileSystem به Database نیاز به تغییر OrderService دارید → وابستگی زیاد است)

آیا در صورت خطا در بایگانی، سیستم کرش می‌کند؟
(اگر کرش کند → مدیریت خطا ضعیف است. باید خطا را لاگ کنید و به پردازش ادامه دهید)

آیا بایگانی در پس‌زمینه (Background) انجام می‌شود؟
(اگر بایگانی همزمان با درخواست‌های کاربر انجام شود → عملکرد سیستم کاهش می‌یابد)

🥉 بخش دوم: تله‌های مرگبار (نمره‌ی زیر ۵۰)
این اشتباهات را هرگز در آزمون Archiveability مرتکب نشوید:

حذف داده‌ها از حافظه قبل از بایگانی:
orders.removeIf(o -> o.getDate().isBefore(cutoff)); // ❌ اول حذف، بعد بایگانی!
archiveStorage.save(removedOrders); // ❌ اگر اینجا خطا بخورد، داده‌ها از بین رفته‌اند
درست: اول بایگانی، بعد حذف.


بایگانی همزمان با درخواست‌های کاربر:
public void addOrder(Order order) {
    orders.add(order);
    archiveOldOrders(); // ❌ بایگانی در همان Thread درخواست!
}

هاردکد کردن مسیرهای بایگانی:
String archivePath = "/var/archive/orders.txt"; // ❌ فقط در لینوکس کار می‌کند

استفاده از Runtime.exec برای فشرده‌سازی:
Runtime.getRuntime().exec("zip archive.zip orders.txt"); // ❌ وابسته به سیستمعامل

نداشتن Fallback برای خطاهای بایگانی:
archiveStorage.save(orders); // ❌ اگر خطا دهد، کل سیستم کرش می‌کند


📜 خلاصه‌ی یک پاراگرافی برای شب امتحان
Archiveability یعنی "قابلیت انتقال داده‌های قدیمی به یک سیستم ذخیره‌سازی بلندمدت بدون تأثیر بر عملکرد سیستم اصلی".
برای رسیدن به آن، یک لایه‌ی انتزاعی (Abstraction) برای بایگانی طراحی کن که بتوانی استراتژی‌های مختلف (فایل، دیتابیس، S3) را بدون تغییر در کد اصلی جایگزین کنی.
عملیات بایگانی باید اتمی (Atomic) باشد: اول داده‌ها را در بایگانی ذخیره کن، بعد از حافظه حذف کن.
بایگانی را در پس‌زمینه و با استفاده از ScheduledExecutorService انجام بده تا تأثیری بر پاسخ‌دهی سیستم نداشته باشد.
هیچ‌گاه داده‌ها را قبل از بایگانی حذف نکن و همیشه خطاهای I/O را مدیریت کن تا سیستم کرش نکند.
