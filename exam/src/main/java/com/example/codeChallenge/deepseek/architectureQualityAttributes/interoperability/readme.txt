🥇 بخش اول: چک‌لیست ۵ ثانیه‌ای Interoperability (قبل از تحویل کد)
وقتی کد را نوشتید، این ۵ سوال را از خودتان بپرسید:

آیا برای اضافه کردن یک فرمت جدید (مثل JSON یا XML)، نیازی به تغییر در کلاس اصلی (مثلاً PaymentService) دارم؟
(اگر بله → یعنی وابستگی به فرمت‌ها در لایه‌ی سرویس باقی مانده است و Strategy Pattern را درست پیاده نکرده‌اید).

آیا از if-else یا switch برای تشخیص نوع فرمت استفاده کرده‌ام؟
(اگر بله → غلط است. باید از Map<Enum, Formatter> استفاده کنید).

اگر یک فرمت پشتیبانی نشود، آیا سیستم کرش می‌کند یا یک پیام خطای مناسب برمی‌گرداند؟
(اگر کرش کند → مدیریت خطا ضعیف است. باید یک Fallback داشته باشید).

آیا جداکننده‌ها و فرمت‌ها در کد هاردکد شده‌اند؟
(اگر بله → تغییر فرمت‌ها سخت است. می‌توانید آنها را به‌عنوان پارامتر یا از پیکربندی بخوانید).

آیا وابستگی‌ها (مثل PaymentFormatterService) از طریق Constructor تزریق می‌شوند؟
(اگر نه → تست‌پذیری پایین است).




🥈 بخش دوم: کلمات کلیدی جادویی برای پاسخ‌های تشریحی (تئوری محض)
اگر سوال تشریحی در مورد Interoperability آمد، حتماً این ۴ عبارت کلیدی را در پاسخ خود قالب کنید:

Abstraction Layer (لایه‌ی انتزاع):
"یک لایه‌ی انتزاعی بین سیستم اصلی و سیستم‌های خارجی ایجاد می‌کنیم تا تغییر در فرمت یا پروتکل سیستم‌های خارجی، تأثیری بر هسته‌ی سیستم نداشته باشد."

Data Format Transformation (تبدیل فرمت داده):
"سیستم باید بتواند داده‌های خود را به فرمت‌های مختلف (JSON, XML, CSV, و غیره) تبدیل کند تا با سیستم‌های ناهمگن ارتباط برقرار کند."

Protocol Independence (استقلال از پروتکل):
"ارتباط با سیستم‌های خارجی نباید به یک پروتکل خاص (مثل HTTP یا JMS) وابسته باشد. با استفاده از اینترفیس‌های مناسب، می‌توان پروتکل را بدون تغییر در منطق اصلی تعویض کرد."

Adapter Pattern (الگوی آداپتور):
"برای اتصال به سیستم‌های خارجی با رابط‌های متفاوت، از Adapter Pattern استفاده می‌کنیم تا تفاوت‌های فرمت و پروتکل را پنهان کنیم."





🥉 بخش سوم: تله‌های مرگبار (نمره‌ی زیر ۵۰)
این اشتباهات را هرگز در آزمون Interoperability مرتکب نشوید:

هاردکد کردن جداکننده‌ها و فرمت‌ها در کد:

java
String result = id + "|" + amount + "|" + currency; // ❌
بهتر است جداکننده‌ها را به‌عنوان فیلد کلاس یا از پیکربندی بخوانید.

استفاده از if-else برای تشخیص فرمت:

java
if (format.equals("LEGACY")) { ... } else if (format.equals("MODERN")) { ... } // ❌
به‌جای آن از Map<Enum, Formatter> و Strategy Pattern استفاده کنید.

برگرداندن null در صورت نبود فرمت:

java
if (formatter == null) return null; // ❌ باعث NPE می‌شود
نمونه‌سازی چندباره در هر درخواست:

java
PaymentFormatterService service = new PaymentFormatterService(); // ❌ هر بار
بهتر است یک نمونه‌ی Singleton یا تزریق شده استفاده شود.

نادیده گرفتن خروجی فرمت‌شده:

java
formatterService.format(LEGACY, tx); // ❌ خروجی دور ریخته می‌شود
خروجی را بگیرید و به سیستم خارجی ارسال کنید.




📜 خلاصه‌ی یک پاراگرافی برای شب امتحان (قابل حفظ کردن)
Interoperability یعنی "ارتباط بدون دردسر با سیستم‌های دیگر". برای رسیدن به آن، یک لایه‌ی انتزاعی (Abstraction) بین سیستم خودت و سیستم‌های خارجی ایجاد کن. از Strategy Pattern برای پشتیبانی از فرمت‌های مختلف استفاده کن و همه‌ی فرمت‌ها را در یک Map<Enum, Formatter> ثبت کن تا با اضافه کردن فرمت جدید، هیچ تغییری در کد اصلی ندهی. هیچ‌وقت جداکننده‌ها و فرمت‌ها را هاردکد نکن و همیشه یک Fallback (مثل UNSUPPORTED) برای مدیریت خطا داشته باش تا سیستم در صورت برخورد با فرمت ناشناخته کرش نکند.

🔥 نکته‌ی طلایی ویژه برای مقایسه (اگر در آزمون پرسیدند)
ویژگی	Maintainability	Modifiability	Testability	Interoperability
تمرکز اصلی	سهولت درک و اصلاح کد	هزینه‌ی تغییرات در سیستم زنده	سهولت نوشتن تست خودکار	ارتباط با سیستم‌های خارجی
ابزار اصلی	SOLID, Design Patterns	پیکربندی پویا (Map)	تزریق وابستگی، Clock	Strategy, Adapter, ServiceLoader
سوال کلیدی	"چند کلاس برای افزودن قابلیت تغییر می‌کند؟"	"برای تغییر نرخ، نیاز به Deploy دارم؟"	"آیا می‌توانم بدون دیتابیس تست کنم؟"	"آیا می‌توانم فرمت JSON را بدون تغییر کد اضافه کنم؟"
نکته‌ی طلایی	از Strategy و Template استفاده کن	از Map و refreshRates استفاده کن	از Constructor Injection و Clock استفاده کن	از Map<Enum, Formatter> و Fallback استفاده کن
💡 نکته‌ی نهایی (برای امتیاز اضافی)
اگر Examiner از شما پرسید: "چه تفاوتی بین Interoperability و Portability وجود دارد؟" پاسخ دهید:

Interoperability مربوط به ارتباط با سیستم‌های خارجی و تبادل داده با فرمت‌ها و پروتکل‌های مختلف است.
اما Portability مربوط به اجرای سیستم در محیط‌های مختلف (ویندوز، لینوکس، JVMهای مختلف) بدون تغییر کد است.
Interoperability به "چگونه با دیگران حرف بزنیم" فکر می‌کند، در حالی که Portability به "چگونه در جایگاه‌های مختلف زندگی کنیم" فکر می‌کند.
