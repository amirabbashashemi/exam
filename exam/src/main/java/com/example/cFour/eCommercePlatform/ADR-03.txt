ADR-03: پیکربندی آسان برای فروشندگان

زمینه و مسئله:
سیستم باید برای کاربرانی مانند محصول، قیمت، تخفیف، موجودی user friendly باشد و براحتی بتوان با آن کار کرد.

وضعیت:
پذیرفته شده

گزینه‌های بررسی‌شده:
ایجاد یک AdminPanel که به کاربر غیر فنی اجازه تعریف قوانین بیزینسی می دهد (کاربر با کشیدن و رها کردن ابزار اگر و آنگاه و .. بتواند یک قانون بسازد)
مزایا:
    جداسازی بیزینس های پنل ها
    مقیاس پذیری
    امنیت بالا
معایب:
    نگهداری سخت سه سورس
    دوباره یا چندباره کاری

استفاده از rule engine Drool برای اجرای قوانینی که در AdminPanel تعریف شده اند
مزایا:
    پویایی در ایجاد قوانین
    ایجاد policy ها بدون تغییر کد و نسخه گذاری
معایب:
    صرف منابع
    هزینه نگهداری بیشتر

استفاده از template های آماده برای کار های رایج مانند تخفیف آخر هفته و ...
مزایا:
    سادگی در پیاده سازی
معایب:
    محدودیت در ایجاد بیزینس

ولیدیشن های سمت فرانت
مزایا:
    جلوگیری از ارسال درخواست ها به backend
    کاربر پسند کردن سیستم و جلوگیری از باگ
معایب:
    امکان دور خوردن ولیدیشن فرانت وجود دارد

تصمیم:
ایجاد یک AdminPanel که به کاربر غیر فنی اجازه تعریف قوانین بیزینسی می دهد (کاربر با کشیدن و رها کردن ابزار اگر و آنگاه و .. بتواند یک قانون بسازد)
استفاده از rule engine Drool برای اجرای قوانینی که در AdminPanel تعریف شده اند
استفاده از template های آماده برای کار های رایج مانند تخفیف آخر هفته و ...

پیامدها:
مثبت:
    با ایجاد پنل ادمین درخواست های پشتیبانی کاهش چشم گیری پیدا می کند و با استفاده از drool میتوان بدون نسخه گذاری و کاملا پویا قوانین جدید تعریف نمود
منفی:
    با افزودن AdminPanel نگهداری سخت تر میشود و single point of falure در مورد rule engine وجود دارد
