ADR-006: رابط کاربری برای سه نقش
وضعیت: پذیرفته شده
تاریخ: ۱۴۰۳
تصمیم‌گیرنده: تیم محصول و معماری

زمینه
سه جور کاربر داریم که نیازاشون زمین تا آسمون فرق داره:
کاربر عادی فقط می‌خواد چت کنه، تماس بگیره، استاتوس بذاره. هرچی ساده‌تر، بهتر.
ادمین گروه (مخصوصاً گروه‌های بزرگ) باید بتونه اعضا رو مدیریت کنه، تنظیمات گروه رو عوض کنه، و برای گروه‌های بالای ۱۰۰۰ نفر، درخواست عضویت رو تأیید کنه.
کسب‌وکارها (مثل فروشگاه‌ها یا پشتیبانی مشتری) نیاز به چیزای کاملاً متفاوتی دارن: ساعت کاری، پاسخ خودکار، کاتالوگ محصولات، و API برای اتصال به سیستم‌هاشون.
اگه بخوایم همه اینا رو تو یه UI واحد بریزیم، تجربه هر سه گروه خراب می‌شه. کاربر عادی گیج می‌شه، ادمین گروه دسترسی لازم رو پیدا نمی‌کنه، و کسب‌وکار نمی‌تونه به سیستمش وصل بشه.

تصمیم
۱. سه اپلیکیشن جداگانه
اپ کاربر عادی رو با React Native می‌سازیم (هم iOS، هم Android). تمرکز فقط روی چت، تماس، و تنظیمات شخصی.
پنل ادمین گروه هم React Native برای موبایل داره، هم React برای Web. چون ادمین گروه‌های بزرگ معمولاً از دسکتاپ کار می‌کنه، نسخه Web خیلی مهم‌تره.
پورتال کسب‌وکار کاملاً Web-based هست. یه داشبورد React + یه REST API + Webhook برای دریافت پیام‌ها.

۲. Design System مشترک
با اینکه سه اپ جدان، ولی ظاهرشون باید شبیه هم باشه. یه کتابخانه کامپوننت مشترک داریم که هر سه ازش استفاده می‌کنن. اینطوری وقتی یه باگ تو دکمه‌ها پیدا می‌شه، فقط یه جا درستش می‌کنیم.
i18next هم برای چندزبانگی استفاده می‌کنیم و RTL/LTR رو با CSS dir هندل می‌کنیم. Dark Mode هم تو هر سه هست.


۳. Business API
کسب‌وکارها نیاز دارن که سیستمشون خودکار به کاربرا پیام بفرسته (مثلاً تأیید سفارش). برای این کار یه REST API داریم که پیام‌های Template رو می‌فرسته.
از اون طرف، وقتی کاربر به کسب‌وکار پیام می‌ده، از طریق Webhook به سیستم اونا اطلاع می‌دیم. یه داشبورد تحلیلی هم داریم که نشون می‌ده چند تا پیام اومده، چند تا جواب داده شده، و میانگین زمان پاسخ چقدره.


۴. Group Admin Panel
ادمین گروه باید بتونه:
عضو اضافه یا حذف کنه
نقش‌ها رو تغییر بده (Admin/Member)
تنظیمات گروه رو عوض کنه (کی می‌تونه پیام بفرسته، کی می‌تونه عضو اضافه کنه)
درخواست‌های عضویت رو تأیید یا رد کنه
برای گروه‌های بزرگ (بالای ۱۰۰۰ نفر)، گزینه "Approve New Members" به صورت پیش‌فرض روشنه تا اسپم کنترل بشه.

گزینه‌های دیگه‌ای که بررسی کردیم
یه UI واحد برای همه: ساده‌ست ولی تجربه هر سه گروه خراب می‌شه. کاربر عادی با تنظیمات پیچیده Business گیج می‌شه.
فقط Mobile: Businessها نیاز به Desktop دارن. کاتالوگ محصولات رو تو موبایل نمی‌شه راحت مدیریت کرد.
بدون Business API: کسب‌وکارهای بزرگ نمی‌تونن وصل بشن. این یعنی از دست دادن بخش بزرگی از بازار.

بدون Design System: سه کدبیس جدا با ظاهر متفاوت. کاربر حس می‌کنه با سه محصول مختلف طرفه.

پیامدها
چیزایی که به دست آوردیم:
هر نقش UI مخصوص خودش رو داره
جداسازی منطق Business از کاربر عادی
امنیت بیشتر (کاربر عادی به APIهای Business دسترسی نداره)
چیزایی که از دست دادیم:
هزینه توسعه سه کدبیس
نگهداری پیچیده‌تر (هر تغییر باید تو سه جا اعمال بشه)
نیاز به تیم Frontend بزرگ‌تر
