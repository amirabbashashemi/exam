ADR-003: پیکربندی آسان برای سازندگان (بدون کد، Asset، منطق بازی)
وضعیت: پذیرفته شده
تاریخ: ۱۴۰۳
تصمیم‌گیرنده: تیم معماری

زمینه و مسئله
فرض کن یه نفر که هیچ کدی بلد نیست، می‌خواد یه بازی بسازه. باید بتونه بدون نوشتن خط کد، منطق بازی رو تعریف کنه.
 از طرف دیگه، حتی برنامه‌نویس‌های حرفه‌ای هم نمی‌خوان همه چیز رو از صفر بنویسن.
  می‌خوان از Assetهای آماده (مدل، صدا، انیمیشن) استفاده کنن.
سه تا مشکل اساسی داریم:
اول، منطق بازی بدون کد. کاربر چطور بگه «اگه بازیکن به دشمن خورد،
 سلامتی کم شه»؟ نمی‌تونیم ازش بخوایم C# یا JavaScript بنویسه.
دوم، Asset Store. هزاران سازنده دارن مدل و صدا و انیمیشن می‌سازن.
 باید یه جایی باشه که اینا رو به اشتراک بذارن و بقیه بتونن استفاده کنن.
سوم، قالب‌های آماده. کاربر تازه‌کار نمی‌دونه از کجا شروع کنه.
 باید یه سری Template آماده داشته باشیم که فقط تغییرشون بده.

تصمیم
تصمیم ۱: Visual Scripting با Node-Based Editor
توضیحات:
به جای نوشتن کد، کاربر با کشیدن و رها کردن Nodeها منطق بازی رو می‌سازه.
هر Node یه عمل داره (مثل «حرکت بده»، «شلیک کن»، «سلامتی کم کن»). کاربر Nodeها رو با خط به هم وصل می‌کنه
و یه منطق کامل می‌سازه. این دقیقاً همون کاریه که Unreal با Blueprints می‌کنه.
مثلاً برای «اگه بازیکن به دشمن خورد،
سلامتی کم شه»، کاربر سه تا Node می‌کشه: «تشخیص برخورد»، «کم کردن سلامتی»، «به‌روزرسانی UI». بعدش با خط به هم وصلشون می‌کنه.
مزایا:
کاربر غیرفنی هم می‌تونه منطق پیچیده بسازه (بدون یادگیری کد)
بصری هست، پس Debugging راحت‌تره (می‌بینی کدوم Node کجا گیر کرده)
می‌شه کد رو هم بهش اضافه کرد (برای حرفه‌ای‌ها)
معایب:
برای منطق‌های خیلی پیچیده، Nodeها زیاد می‌شن و صفحه شلوغ می‌شه
Performance کمتر از کد خالص (چون هر Node یه لایه Abstraction داره)
نیاز به آموزش داره (کاربر باید Nodeها رو بشناسه)


تصمیم ۲: Asset Store با S3 + CDN + Versioning
توضیحات:
سازنده‌ها Assetهاشون (مدل سه‌بعدی، صدا، انیمیشن، تکسچر) رو تو S3 آپلود می‌کنن. CDN اونا رو توزیع می‌کنه تا همه سریع دانلود کنن. هر Asset یه نسخه داره و می‌شه نسخه‌های قدیمی رو هم دید. کاربرا می‌تونن Assetها رو رایگان یا پولی استفاده کنن.
مزایا:
دسترسی سریع (CDN از نزدیک‌ترین سرور به کاربر سرویس می‌ده)
نسخه‌بندی (اگه یه Asset آپدیت شد، پروژه‌های قدیمی خراب نمی‌شن)
Monetization (سازنده‌ها می‌تونن Assetهاشون رو بفروشن)
معایب:
هزینه S3 + CDN (برای Assetهای حجیم، ماهانه چند هزار دلار)
نیاز به Moderation (شاید کسی Asset نامناسب آپلود کنه)
پیچیدگی مدیریت نسخه‌ها (کی، کِی، چی رو آپدیت کرد)


تصمیم ۳: Template Library با قالب‌های آماده
توضیحات:
یه سری قالب آماده برای انواع بازی داریم: Platformer، Shooter، Puzzle، Racing، RPG. کاربر یه قالب رو انتخاب می‌کنه، بعد فقط Assetها و منطقش رو تغییر می‌ده. اینطوری نیازی نیست از صفر شروع کنه.
قالب‌ها تو PostgreSQL به صورت JSONB ذخیره می‌شن. هر قالب شامل یه Scene از پیش ساخته شده، چند Asset پیش‌فرض، و منطق پایه‌ست. کاربر می‌تونه هر کدوم رو تغییر بده.
مزایا:
کاربر تازه‌کار در ۵ دقیقه یه بازی قابل بازی می‌سازه
Best Practiceها منتقل می‌شن (کاربر یاد می‌گیره چطور بازی حرفه‌ای بسازه)
کاهش پشتیبانی (کاربرا کمتر سوال می‌پرسن)
معایب:
نگهداری قالب‌ها هزینه داره (هر تغییر تو موتور بازی، قالب‌ها باید آپدیت بشن)
محدودیت در خلاقیت (شاید کاربر بخواد چیزی خارج از قالب بسازه)
تعداد قالب‌ها محدوده و نمی‌تونه همه سلیقه‌ها رو پوشش بده

تصمیم ۴: Rule Engine برای قوانین بازی
توضیحات:
برای منطق‌های ساده (مثل «اگه امتیاز > ۱۰۰، Level بعدی باز شه»)، از یه Rule Engine استفاده می‌کنیم. قوانین تو PostgreSQL (JSONB) ذخیره می‌شن. کاربر با یه فرم ساده، قانون If-Then تعریف می‌کنه. این قوانین تو Runtime اعمال می‌شن.
مزایا:
برای منطق‌های ساده، سریع‌تر از Visual Scripting
کاربر بدون کشیدن Node، قانون تعریف می‌کنه
قابل تغییر در Runtime (بدون نیاز به Recompile)
معایب:
فقط برای منطق‌های ساده مناسبه (برای پیچیده، باید Visual Scripting بره)
نیاز به Drools داره (پیچیدگی تیم فنی)
اگه قانون اشتباه باشه، ممکنه بازی خراب بشه


گزینه‌های بررسی‌شده
الف) فقط کد (Text-based Scripting):
مزایا: قدرت کامل، Performance بالا
معایب: کاربر غیرفنی نمی‌تونه استفاده کنه، آموزش سخت

ب) فقط Template (بدون تغییر):
مزایا: سادگی، سرعت
معایب: محدودیت شدید، کاربر نمی‌تونه خلاقیت داشته باشه

ج) Block-based (مثل Scratch):
مزایا: برای بچه‌ها عالیه
معایب: برای بازی‌های حرفه‌ای محدوده، کاربر بزرگسال باهاش ارتباط نمی‌گیره

د) Asset Store بدون Versioning:
مزایا: سادگی
معایب: اگه یه Asset آپدیت بشه، پروژه‌های قدیمی خراب می‌شن

پیامدها
چیزایی که به دست آوردیم:

کاربر غیرفنی هم می‌تونه بازی بسازه (با Visual Scripting)

Assetهای آماده به سرعت در دسترسن (با CDN)

شروع سریع با Templateها

منطق‌های ساده با Rule Engine سریع تعریف می‌شن
