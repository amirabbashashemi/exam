ADR-012: امنیت ارتباطات داخلی با mTLS و RBAC در API Gateway
وضعیت: پذیرفته شده

زمینه:
ارتباط بین میکروسرویس‌ها باید امن باشه. اگه کسی به شبکه داخلی دسترسی پیدا کنه، نباید بتونه ترافیک رو شنود کنه یا خودشو جای یه سرویس جا بزنه. از طرف دیگه، دسترسی‌ها باید بر اساس نقش کنترل بشه.

تصمیم:

mTLS (Mutual TLS) برای همه ارتباطات بین سرویس‌ها

Certificateهای X.509 از CA داخلی

RBAC در API Gateway (Kong)

JWT با Claim نقش برای Authorization

Certificate Rotation هر ۹۰ روز

دلیل تصمیم:
mTLS یعنی هر سرویس باید Certificate معتبر داشته باشه. اگه مهاجم به شبکه دسترسی پیدا کنه، بدون Certificate نمی‌تونه خودشو جای سرویس جا بزنه. RBAC در Gateway یعنی کنترل دسترسی متمرکز.

مزایا:

جلوگیری از Man-in-the-Middle

احراز هویت متقابل سرویس‌ها

کنترل دسترسی متمرکز (RBAC)

Certificate Rotation خودکار

معایب:

Overhead در CPU (رمزنگاری/رمزگشایی)

مدیریت Certificate پیچیده

Debugging سخت (ترافیک رمزنگاری‌شده)

نیاز به CA داخلی
