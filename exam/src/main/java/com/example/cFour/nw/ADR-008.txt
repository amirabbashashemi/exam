ADR-008: استراتژی Versioning در APIها
وضعیت: پذیرفته شده

زمینه:
Clientهای مختلف (موبایل، وب، Desktop) نسخه‌های مختلف دارن. اگه API رو تغییر بدیم، Clientهای قدیمی خراب می‌شن. کاربرا هم نمی‌تونن فوری آپدیت کنن.

تصمیم:

URL Versioning: /api/v1/...، /api/v2/...

هر Version حداقل ۶ ماه پشتیبانی می‌شه

Deprecation اعلام ۳ ماه قبل

Breaking Change فقط در Version جدید

دلیل تصمیم:
URL Versioning ساده‌ترین و قابل‌فهم‌ترین روشه. Clientها می‌دونن کدوم Version رو صدا بزنن. مستندات جداگانه برای هر Version.

مزایا:

Clientهای قدیمی کار می‌کنن (بدون شکستن)

مهاجرت تدریجی و بدون فشار

مستندات جداگانه برای هر Version

Debugging ساده (از URL می‌فهمی کدوم Version)

معایب:

نگهداری چند Version (کد Duplicate)

تست بیشتر (هر Version جدا)

پیچیدگی Deploy (چند نسخه همزمان)

Debt فنی (Versionهای قدیمی)
