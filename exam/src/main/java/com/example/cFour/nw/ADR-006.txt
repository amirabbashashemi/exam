ADR-006: استفاده از Schema Registry و Contract-First Design
وضعیت: پذیرفته شده

زمینه:
تیم‌های Stream-aligned به صورت مستقل کار می‌کنن. اگه هر تیم داده رو با فرمت خودش بفرسته، ارتباط بین سرویس‌ها می‌شکنه. باید استانداردسازی بشه.

تصمیم:

استفاده از Avro/Protobuf برای Schema

Schema Registry (Confluent) برای مدیریت Version

Contract-First: هر سرویس اول Contract خودش رو با OpenAPI تعریف می‌کنه

Kafka با Schema Registry برای Eventها

دلیل تصمیم:
Schema Registry تضمین می‌کنه که داده‌ها با فرمت یکسان رد و بدل بشن. Contract-First یعنی تیم‌ها موازی کار می‌کنن. اگه Schema تغییر کنه، Versioning انجام می‌شه و Compatibility بررسی می‌شه.
