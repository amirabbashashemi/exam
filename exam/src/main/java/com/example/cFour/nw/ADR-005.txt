ADR-005: معماری i18n و پشتیبانی از RTL/LTR
وضعیت: پذیرفته شده

زمینه:
پلتفرم باید از چندین زبان (فارسی، انگلیسی، عربی، ترکی) پشتیبانی کنه. زبان‌های RTL (فارسی، عربی) نیاز به چیدمان برعکس دارن. اعداد و تاریخ هم باید محلی باشن.

تصمیم:

i18next برای UI

UTF-8 در تمام دیتابیس‌ها

Elasticsearch Analyzer مجزا برای هر زبان (persian_analyzer, english_analyzer)

CSS dir="rtl" برای RTL

اعداد و تاریخ محلی با Intl.NumberFormat و Intl.DateTimeFormat

دلیل تصمیم:
i18next استاندارد صنعتی برای i18n در React هست. UTF-8 تضمین می‌کنه که همه کاراکترها درست ذخیره بشن. Elasticsearch Analyzer مجزا یعنی جستجو در هر زبان دقیق انجام می‌شه.

مزایا:

پشتیبانی کامل از چند زبان (بدون نسخه‌گذاری)

RTL/LTR خودکار بر اساس زبان

جستجوی دقیق در هر زبان

معایب:

هر زبان یه فایل JSON جداگانه نیاز داره (نگهداری بیشتر)

ترجمه‌ها باید توسط انسان بازبینی بشن

بعضی کامپوننت‌های شخص ثالث با RTL سازگار نیستن
