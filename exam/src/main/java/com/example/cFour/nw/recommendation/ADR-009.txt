ADR-009: معماری Tiered Storage برای داده‌های حجیم
وضعیت: پذیرفته شده

زمینه:
داده‌های کاربران و تعاملاتشون روز به روز زیاد می‌شه. نگه‌داری همه چیز در PostgreSQL باعث کندی و هزینه نجومی می‌شه. از طرف دیگه، بعضی داده‌ها قدیمی‌ان و کم استفاده می‌شن ولی باید برای Audit بمونن.

تصمیم:

Hot (۰-۶ ماه): PostgreSQL + Redis

Warm (۶ ماه - ۲ سال): Elasticsearch

Cold (> ۲ سال): S3 Glacier

Job شبانه برای انتقال خودکار

بازیابی از Glacier: ۳-۵ ساعت (با اطلاع‌رسانی)

دلیل تصمیم:
هر داده تو دیتابیسی که برای سنش مناسبه ذخیره می‌شه. داده‌های اخیر سریع، داده‌های قدیمی ارزون. اینطوری هم Performance حفظ می‌شه هم هزینه کاهش پیدا می‌کنه.

مزایا:

داده‌های قدیمی برای Audit باقی می‌مونن

Compliance با قانون (نگه‌داری ۷ ساله)
