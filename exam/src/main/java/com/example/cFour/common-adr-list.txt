چالش «سازگاری (Consistency)»
Decision:
۱. Ordering (ترتیب)
   - Lamport Timestamp (برای رویدادهای Distributed)
   - Sequence Number (برای پیام‌های یک Conversation)
   - Vector Clock (برای Causality)

۲. Conflict Resolution (حل تعارض)
   - CRDT (برای متن/سند) → Yjs/Automerge
   - OT (برای Editor مرکزی) → Google Docs
   - Last-Write-Wins (برای تنظیمات ساده)
   - Versioning + Manual (برای فایل)

۳. Atomicity (اتمی بودن)
   - Saga Pattern (برای Distributed Transaction)
   - Two-Phase Commit (برای DBهای محدود)
   - Idempotency Key (برای Retry)

۴. Idempotency (جلوگیری از تکرار)
   - Client Message ID (UUID)
   - Redis SETNX با TTL=۲۴h

۵. Eventual Consistency
   - Kafka برای Event Propagation
   - CDC (Debezium) برای DB → DB

Alternatives:
- Strong Consistency (2PC): رد شد چون Availability را کم می‌کند
- Last-Write-Wins: رد شد چون تغییرات از دست می‌رود
- Locking: رد شد چون UX بد

Consequences:
مثبت: مقیاس‌پذیری، Availability
منفی: پیچیدگی، Eventual Consistency
ریسک: Conflict → CRDT خودکار حل می‌کند
