منفی: تأخیر Restore، پیچیدگی Job

ریسک: اگه Job خطا کنه → DLQ و Retry و Alert

ADR-009: انتخاب مکانیزم برای احراز هویت و مدیریت Session
وضعیت: پذیرفته شده

زمینه:
پلتفرم باید احراز هویت امن برای میلیون‌ها کاربر فراهم کنه. پسورد ساده کافی نیست. اگه پسورد لو بره، حساب کاربر نباید بره. از طرف دیگه، Session باید قابل Revoke باشه.

تصمیم:
از OAuth 2.0 + OIDC با JWT (Access Token کوتاه‌مدت) و Refresh Token (Opaque، در HttpOnly Cookie) به همراه MFA استفاده می‌کنیم.

دلیل تصمیم:
OAuth 2.0 استاندارد صنعتیه. JWT کوتاه‌مدت (۱۵ دقیقه) یعنی اگه لو بره، فقط ۱۵ دقیقه معتبره. Refresh Token تو HttpOnly Cookie ذخیره می‌شه که JavaScript نمی‌تونه بهش دسترسی داشته باشه (جلوگیری از XSS). MFA هم یعنی مهاجم حتی با پسورد، نمی‌تونه وارد بشه.

مزایا:

امنیت بالا با MFA

Session امن با HttpOnly Cookie

Revoke فوری Refresh Token

استاندارد صنعتی (Keycloak)
