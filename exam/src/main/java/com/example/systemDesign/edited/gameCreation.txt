ADR-001: Runtime Engine برای Cross-Platform
وضعیت: پذیرفته شده

زمینه:
بازی هایی که توسط کاربران ساخته می شوند باید روی ویندوز، لینوکس و مک اجرا شوند.
عقلانی نیست برای هر سیستم عامل کد جداگانه تولید کرد.
باید یه لایه ی میانی داشته باشیم که یه بار نوشته بشه و همه جا کار کنه.

تصمیم:
استفاده از WebAssembly (WASM) به عنوان Runtime اصلی و Electron برای پوسته ی دسکتاپ استفاده می کنیم.

دلیل تصمیم:
با WASM یه بار کامپایل می شه و روی هر OS و حتی مرورگر اجرا می شود.
و  Electron هم دسترسی به فایل سیستم و سخت افزار رو فراهم می آورد.
این ترکیب یعنی یه کدبیس برای همه پلتفرم ها.

مزایا:
یه کدبیس برای ویندوز، لینوکس، مک و مرورگر
Sandbox امن برای کد کاربر
راه اندازی سریع (زیر ۵۰ میلی ثانیه)
اجرای بازی تو مرورگر بدون نیاز به نصب
معایب:
Performance کمی پایین تر از Native، مخصوصاً تو گرافیک سنگین
دیباگ کردن کد WASM سخت تره
بعضی کتابخانه های C++ هنوز پشتیبانی کامل ندارن
حجم Bundle Electron سنگینه
موارد دیگر بررسی شده:

الف) کد Native برای هر OS:
مزایا:
بهترین Performance
دسترسی کامل به سخت افزار
معایب:
سه کدبیس جدا
نگهداری خیلی سخت
تیم بزرگ لازمه

ب) Unity یا Unreal:
مزایا:
زیرساخت آماده
Cross-platform خودکار
معایب:
وابستگی به شرکت خارجی
هزینه لایسنس
ما خودمون می خوایم پلتفرم ساخت بازی باشیم، نه کاربر

ج) فقط وب (بدون دسکتاپ):
مزایا:
سادگی
بدون نصب
معایب:
دسترسی محدود به سخت افزار
Performance پایین
تجربه ی ضعیف برای بازی های سنگین

پیامدها:
مثبت: یه کدبیس، Sandbox امن، Cross-platform
منفی: Performance کمتر، پیچیدگی WASM

ADR-003: ذخیره سازی پروژه با نسخه بندی
وضعیت: پذیرفته شده

زمینه:
سازنده ها بازی ها را می سازند و ممکن است هر لحظه تغییراتشون رو ذخیره کنند.
اگه تغییر بزرگی بدن و بعد پشیمان شنو، باید بتونند به نسخه ی قبل برگردند. حجم پروژه ها هم می تونه زیاد باشه.

تصمیم:
از Op Log + Snapshot با Cassandra و S3 استفاده می کنیم.

دلیل تصمیم:
هر تغییر به صورت یه Operation ثبت و تو Cassandra ذخیره می شه.
هر ۱۰۰۰ تغییر، یه Snapshot کامل تو S3 ذخیره می شود.
برای بازگردانی، آخرین Snapshot قبل از نسخه ی هدف رو می گیریم و Opهای بعدش رو اعمال می کنیم.
این روش حجم ذخیره سازی رو بهینه می کند.

مزایا:
کاربر می تونه به هر نسخه ای برگرده
حجم ذخیره سازی بهینه (Snapshot + Delta)
Audit Trail کامل
Write سریع با Cassandra
معایب:
پیاده سازی پیچیده (Op Log و Replay)
نیاز به Job برای Snapshot دوره ای
Replay ممکنه برای پروژه های بزرگ کند باشه
مدیریت State سخت

معایب:
